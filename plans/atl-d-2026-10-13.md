# ATL-D / ATEL-D plan (issue #3, item 1)

Source: Galimullin, Grosinger & Mittelmann, *I Would If I Could*, KR 2026,
doi:10.24963/kr.2026/31 (local PDF under
`~/Projects/Logic/logic-notes/reference/dynamic-strategic-logics/pdfs/`; not
committed). Read so far: Defs 1-4, the update semantics, Example 1, Algorithm 1,
Defs 8-9, 11. **Not yet read:** the expressivity proofs, the complexity proofs,
and ATEL-D's strategy clause for `⟨⟨A⟩⟩`. Cite definition numbers only after
checking them against the PDF.

## Semantics to implement

- **Models.** A CGS `(V, ℓ, d, o)` as in `Gamen.Cgs`, except `o` must be defined on
  *all* joint actions, including ones not currently available ("disabled"
  transitions that a grant can enable).
- **`has(a, α)`** holds at `v` iff `α ∈ d(a, v)`.
- **Updates** `[φ1:α1→A1, …, φk:αk→Ak]±ψ`. Every `φi` is evaluated in the
  *current* model at every state, simultaneously (not chained). Then:
  - grant: `d'(a,v) = d(a,v) ∪ {αi | v ⊨ φi, a ∈ Ai}`;
  - revoke: `d'(a,v) = d(a,v) \ {…}`, unless that would empty `d(a,v)`, in which
    case `a` keeps all of `d(a,v)` there ("reasonableness"). `o` is unchanged.
  - then `ψ` is checked in the updated model. Algorithm 1 is exactly this
    recursion, so it fits `sat`'s global style: recurse for the `φi` sets, build
    `d'`, recurse on `ψ`.
- **ATEL-D** adds `K_a`, and each update clause gets an "informed" set `B`:
  `∼'_a = ∼_a ∩ ∼φi` for `a ∈ Ai ∪ Bi`, where `∼φ` is the φ/¬φ partition of the
  current model.
- Also in the paper: the release operator `⟨⟨A⟩⟩φRψ` (gamen-lean has `X`, `G`,
  `F`, `U` only).

## Design decisions needed from Brian

1. **Disabled transitions in the JSON spec.** `CgsJson` currently requires a
   complete table over *available* joint moves. ATL-D needs it over the whole
   action universe, which can blow up (the 256-state downstream model). Options:
   (a) require the full table; (b) add `default_next` for unlisted joint moves
   (a modeling choice: for example, stay in place); (c) allow `transition_rule`
   data. Recommend (b), with an explicit field and a documented meaning.
2. **Where the new formulas live.** An update holds a *list* of
   `(condition : Formula, action, agents)`, which makes `Formula` a nested
   inductive. That risks `deriving BEq, Ord, DecidableEq, Hashable` and the
   `sizeOf` termination lemmas (`immediateSubformulas`, `toNNF`), and adds an
   arm to about 30 `canUntil` sites in 16 files. Recommend a separate
   `Gamen.Atl.Dynamic.DFormula` (bot, atom, connectives, `has`, `K`,
   `canNext/Always/Eventually/Until/Release`, `grant`, `revoke`) with its own
   JSON codec and `toFormula? : DFormula → Option Formula`. That keeps the
   existing 30-constructor ADT, gamen-hs compatibility and `Formula`'s proofs
   untouched, and it gives a differential test (below).
3. **Scope of the first PR.** Recommend ATL-D (perfect information) first, ATEL-D
   as a second PR.

## Phases

1. **`Gamen/Atl/Dynamic.lean`** (perfect information). `DFormula`; `updateCgs`
   (grant and revoke with the reasonableness rule); `dsat : Cgs → DFormula →
   Except String (TreeSet s)` recursing like Algorithm 1; `release` as a
   greatest fixpoint through the existing fuel-bounded `gfp`. No `partial def`.
2. **Codec and protocol.** Extend `CgsJson` (decision 1); add the `DFormula`
   decoder (`has`, `grant`/`revoke` with `updates: [{condition, action,
   agents}]`); accept either formula type in `atl_model_check` (a `"dynamic":
   true` field, or detection by operator); bump `protocolVersion` to 3. Existing
   request types stay byte-identical; run `compare.py`.
3. **Tests.**
   - *Differential:* on the update-free fragment, `dsat` equals `Gamen.Atl.sat`
     over random CGSs (reuse the existing property helpers).
   - *Answer key:* Example 1 (oxygen tank, Fig. 1-2) with its two stated formulas.
     The figure's text extracts garbled, so rebuild the model from the figure
     itself, not from my reading of it.
   - *Properties:* updates are simultaneous (an update whose conditions mention
     `has`); reasonableness keeps every `d'(a,v)` non-empty; grant is idempotent;
     revoking then granting the same action restores `d` only when nothing was
     refused.
   - *Plant a bug* in `updateCgs` (drop reasonableness; chain instead of
     simultaneous) and confirm a test fails.
4. **ATEL-D** (second PR). Add informed sets, `∼'` refinement, `K`; reuse
   `mkAtelModel` after each update as a runtime invariant check (equivalence
   relation, uniform moves). Read the paper's ATEL-D strategy clause first, to
   decide between `atlirSat` and the objective variant.
5. **Docs.** `PORTING.md` Lean-only section, `Validate.lean` protocol text, a
   `docs/` note. Do not copy the paper into the repo.

## Out of scope (for now)

- Bounded update existence (NP-complete in the paper): a brute-force search over
  ≤ n updates could follow, but it is not needed to answer the "does the
  guarantee survive losing the clinician?" question.
- Social-law translation (Theorems 3-4) needs Galimullin & Kuijer 2024, which is
  not local.
- Items 2-4 of issue #3.

## Status (2026-10-13)

Phases 1-3 and ATEL-D (phase 4) are done. ATEL-D: the paper never states the
`⟨⟨A⟩⟩` clause (Defs 8-11 and Algorithm 2 say only "memoryless uniform strategy
w.r.t. the updated relation"), so `Gamen.Atl.Dynamic` offers subjective (default,
as `atlirSat`) and objective, chosen by `semantics`. Later the extended version
(`galimullin2026iwiic-extended.pdf`) arrived; its Example 2 says "no uniform
strategy … from all states the robots consider indistinguishable", so subjective is
what the authors mean, and Example 2 is now an answer-key test. Galimullin & Kuijer
2024 (`galimullin2024slam.pdf`, a 3-page abstract) defines atomic social laws; the
ATL-D paper's Theorem 4 (`[ζ]φ ⇔ [π_ζ]−φ`) is a differential test against a model
built from that definition. Bounded update existence is done as a finite-pool search (`Gamen/Atl/UpdateSearch.lean`, `atl_update_search`): it does not search over every condition formula, and its size is a clause count, not the paper's symbol count. Theorem 3 is a differential test too
(`Gamen/Atl/SocialLaws.lean`, `Tests/SocialLaws.lean`): its source is van der Hoek,
Roberts & Wooldridge, Synthese 156(1):1-19 (2007), §4, which defines behavioural
constraints, implementation `S † β` and effectiveness (an earlier note here named
Alechina, Logan & Dastani 2018, which the ATL-D paper cites only as an overview, and
which does not cover them). The two agree for reasonable constraints; an unreasonable one
is an error in vdHRW and a keep-everything fallback in ATL-D. Nothing left on item 1
except what was not read: the complexity proofs (Algorithms 1-2, Theorems 5-7) and the
expressivity results.
